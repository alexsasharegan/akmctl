# AKM API schemas and fixtures

The JSON Schemas (`schemas/`), the validator (`validate.js`) and the conformance fixtures (`.fixtures/`) of the AKM API. The contract they belong to is [akm-api-spec](../akm-api-spec.md); the standard is [agent-ready-repo-spec](../agent-ready-repo-spec.md).

`.fixtures/` is the one source of the conformance fixtures. Edit the cases and sample repositories there. The directory starts with a dot so a notes vault does not index the sample records; Prettier ignores it, because the fixtures are byte-exact.

The Go tests read a copy: `testdata/api` and `testdata/yaml-lite.json` at the repository root. After a change run `scripts/sync-fixtures.sh` and commit both; `TestFixtureCopiesAgree` (`go test ./internal/api`) fails, naming the files, when the copy differs from the source in any file or byte (work item [261029-x4ws](../../work/done/261029-x4ws-single-source-api-fixtures.md)). `make_fixtures.py` stays in the source only.

`.fixtures/make_fixtures.py` is a frozen reference for how the two sample repositories were built, not a generator to run: it no longer knows every case (`bases`, `show-3`, `ls-7`, the newer `close` and `init` cases), and running it rewrites cases that are kept by hand. Add or change a case by editing its JSON file (write only `name`, `repo`, `request` and `"expected": {"operation": "<op>"}` for a new one), run `scripts/sync-fixtures.sh`, then `go test ./internal/conformance -run TestConformance -update`: it rewrites `expected` (and `after`, `would_be`) from the tool's own output in both copies, and the diff is the review. It keeps the matchers (`$any`, `$id(..)`, `$hash`) that the old `expected` has where the new output still fits them; a value that should become a matcher (a random id, a git hash) is replaced by hand afterwards. `-update` runs the first binding of the case only, so run the test again without it. Check the new response by eye; the test passes whatever the tool says.

`go test ./internal/conformance` runs every case through the API, the HTTP handler and, for reads, the command line. A case may carry `git` (a history to replay) and `bindings` (to restrict it); the format is in section 9 of the [API spec](../akm-api-spec.md) and ADR 261108-15dw.
