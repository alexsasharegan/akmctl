# Architecture

`akmctl` reads a repository's AKM records (work items, ADRs, the roadmap, the manifest `.layout`, `docs/.layout` by default) and offers one set of operations over them through two bindings: a command line and a loopback HTTP server. The contract is the AKM API spec in `docs/spec/akm-api-spec.md`; the fixtures in `testdata/api/` are its executable form, a copy of `docs/spec/akm-api/.fixtures` kept in step by hand (work item 261029-x4ws).

The words used here are defined in [glossary.md](glossary.md).

## Invariants

These invariants serve a broader design goal: **knowledge-system integrity**. `akmctl` must preserve user-authored records beyond the spans it intentionally edits, keep its specification, validation and mutation behavior in agreement, and keep externally observable behavior aligned with the contracts and documentation that describe it. A change that breaks any of these relationships can leave the records, the tool, or its consumers with conflicting understandings of the same information.

- Standard library only in the tool; `go.yaml.in/yaml/v3` is a test oracle and never linked into the binary.
- Large specifications (YAML, Markdown) are read by our own narrow implementation of the subset the records use, checked against an oracle library that is test-only, and the tool fails closed outside that subset: it refuses and names the construct, and writes nothing (ADR 261031-nvka).
- `init` never overwrites a file; versions in what it writes come from the tool's constants (`check.LayoutVersion`), not from templates. `internal/initrepo/templates/skills` is a copy of `.agents/skills`, kept equal by a test.
- The manifest, `.akm-deny`, `.akm.lock` and `.akm-migrate-log` share one folder (`docs/` by default), found by `record.Locate`: `docs/.layout`, else exactly one `<name>/.layout` among the root's immediate non-hidden subdirectories; two is an error. No code hard-codes `docs/` for them.
- The tool never stages, commits or pushes; it describes a step's commit (`commit` member) and `commits` reads git history, read-only. `close` renames; `new adr` does not regenerate the index (`index` does).
- A write is a compare-and-swap on an etag under the repository lock, written by temp file and rename.
- Unknown frontmatter keys, comments, quoting and line endings survive every edit byte for byte.
- Records the tool writes use bare ids unless the manifest sets `reference_style: wikilink`.
- The CLI and the HTTP binding return the same JSON envelope for the same request.
- `testdata/` is byte-exact: `.gitattributes` turns line-ending conversion off for it.
- The API fixtures have one source, `docs/spec/akm-api/.fixtures`; `testdata/api` and `testdata/yaml-lite.json` are a copy that `scripts/sync-fixtures.sh` writes and `TestFixtureCopiesAgree` checks.

## Platform coverage

Windows is checked in CI on the `windows-latest` runner, where the job blocks (ADR 261029-eegx names the tiers). Two layers:

- `go test ./...` runs on all three runners: unit and integration tests, including the lock and rename behavior of the repository writer.
- The Windows smoke harness (`scripts/windows-smoke.ps1`, run through `pwsh`) is the real behavior: it takes the built `akmctl.exe` and runs init, new, set, section, claim, close (a file move that rewrites links) and check on a temporary repository in a directory with spaces, once with `core.autocrlf=true` (the records are checked out with CRLF) and once with `false`. It also passes a `--repo` with mixed separators, writes while a reader holds a record (one that shares delete, and one that does not), and fails on a wrong exit code, a mixed line ending, a leftover `.akm.lock` or a link that gained a backslash.

What runs where:

| Behavior                                                                                     | macOS and Linux (local and CI)                                                                                                      | Windows runner (CI)                                                                                         |
| -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Compiles for Windows                                                                         | `GOOS=windows go vet ./...` and `GOOS=windows go test -c -o /dev/null ./internal/...` (one package at a time)                       | `go vet ./...` and `go test ./...`                                                                          |
| CRLF records: every write keeps the file's endings, `close` rewrites links with `/` and CRLF | `TestWritesOnACRLFCheckout` in `internal/api`, plus the CRLF cases in `internal/body`, `internal/frontmatter` and `internal/record` | the same tests, and the smoke harness with `core.autocrlf=true`                                             |
| Path style (`\` separators, drive letters, `C:\Users\...`)                                   | not simulated: on macOS and Linux a backslash is a legal file name character, so a test would check something else                  | `filepath` code on its own platform, and the harness (spaced path, backslashes, a mixed-separator `--repo`) |
| Locks, rename over a file, a reader holding a record                                         | not possible                                                                                                                        | the repository lock tests in `go test`, and the harness                                                     |
| A console (prompts, colors, `ui`)                                                            | by hand                                                                                                                             | not covered (work item 261108-ct4s)                                                                         |

A change to code that touches paths, line endings, locks or renames is checked locally with the first two rows, then by the Windows job, which stays the final check. The harness also runs on macOS and Linux when `pwsh` is installed. The environment for real Windows behavior is the runner, not a VM or Wine (maintainer's decision, 2026-11-08; work item 261028-jzsx).

## Where the standard lives

This repository holds the whole of AKM: the standard (`docs/spec/agent-ready-repo-spec.md`), the guide (`docs/spec/akm-guide.md`), the API spec (`docs/spec/akm-api-spec.md`) with its schemas, validator and fixtures (`docs/spec/akm-api/`), the decisions that shaped them (`docs/adr/`, `docs/design/agent-ready-repo-decision-log.md`) and the closed work (`docs/work/done/`). `docs/ideas/` holds ideas that are not part of AKM (not records; `check` skips them). There is no template repository; `akmctl init` and `akmctl migrate` are the way in (ADR 261029-j0d0).

## Versions

The tool, the standard (layout) and the API are versioned independently: the tool is 0.x, the layout in the manifest is 0.3.0, the API is 1.0. The tool's version is stamped at build time from the git tag; there is no `VERSION` file.
