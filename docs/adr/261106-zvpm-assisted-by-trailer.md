# Agents attribute with an Assisted-by trailer

## Context

Decision 261101-z0mt made every agent commit end with `Co-Authored-By: <agent and model> <noreply address>` and every pull request description end with a line naming the agent. Claude Code's own default for that line reads "Generated with Claude Code" with a robot emoji. The maintainer works with a human in the loop on every change, reviews each pull request and decides what lands, so "co-author" and "generated" both overstate the agent's part and give readers the wrong impression of how the work was made. A shared rule has to hold for every model, so the wording cannot be a Claude Code setting alone.

## Considered Options

- Keep `Co-Authored-By`: GitHub then lists the agent as a co-author on the commit, which is the claim the maintainer does not want to make.
- Drop attribution: readers lose the record of which tool and model took part.
- `Assisted-by: <agent and model>` on commits and an "Assisted by <agent>" line on pull requests: says the tool assisted and the human decided.

## Decision

Commits end with `Assisted-by: <agent and model>` after the `AKM-` trailers, and a pull request description ends with one line, `Assisted by <agent>`. No robot emoji, and never "generated by". Everything else in 261101-z0mt stands (a pull request for every agent, one work item per branch, the maintainer merges). The maintainer's user-level instructions say the same; this repository's `AGENTS.md` names the trailer so that it holds for any agent that reads only the repository. Decided by Alexander on 2026-11-06.

## Consequences

- GitHub no longer shows the agent as a co-author; the trailer still records the tool and model in `git log`.
- Commits made before this change keep their `Co-Authored-By` trailers; nothing rewrites them.
- No rule in `commits` checks the trailer, so no code changes.
