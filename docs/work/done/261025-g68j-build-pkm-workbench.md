# Build pkm-workbench, milestone one

## Goal

Build the local PKM server designed in [[pkm-workbench-design]]: a Go standard-library program that serves the task views from the vault's files and writes changes back to the YAML frontmatter. Repo: `~/github.com/alexsasharegan/pkm-workbench` (new, own repo, Go module `github.com/alexsasharegan/pkm-workbench`; short names `pkm-wb`, `pkmwb`). Code stays out of the vault.

## Milestone one

1. Create the repo and read the tasks folder; render the Next and active view, read-only, on `127.0.0.1` with the token and Origin checks.
2. Add the other views from the spec in the design note, and a check that compares the server's lists with `Tasks.base` on the same files.
3. Status change by drag, with the file hash check and atomic write.
4. Close prompt with a required outcome (sets `status` and `updated_at`; puts `## Outcome` above `## Log`, deletes `## Next`).

Also in this task, in the vault: add `raw` to the status vocabulary in [[Tasks]] and to the field registry; decide where the view spec lives (the hub, per the design note); write the UI design brief for an agent with no context on the Vault Views kit.

Done when: the four steps work against the real task folder, with tests for parsing, the line edit and the hash check; a README in the repo; the repo location recorded in [[Vault Views]]. Not in scope: phone access, the file watcher, the close cascade and the ADR check dialog (pinned under Later in the design note).

## Outcome

Milestone one is built and in use: the read-only views (checked against `Tasks.base` by `pkm-wb check`), the board, hash-checked atomic status changes, and the close wizard with a required outcome. Beyond it: blocked and raw-refine wizards, direct moves with undo, capture, watch mode with a basic animation, an easy start (`pkm-wb`), and the new status vocabulary. Repo `~/github.com/alexsasharegan/pkm-workbench`, head `3bf9da1` (pushed); README and `ROADMAP.md` in the repo; recorded in [[Vault Views]]. Tests cover parsing, the line edit and the hash check.
Verified on the real vault: the views against Obsidian (`pkm-wb check`), Alexander ran the app and captured a real note through it. Server moves on the real vault were not exercised by me; all my write tests ran on copies.
Left for the follow-up tasks: delete, sort, filter, priority, timestamps ([[261026-np3c-workbench-delete-task]], [[261026-mrdr-workbench-sort]], [[261026-zg0g-workbench-filter]], [[261026-tesh-task-priority-flag]], [[261026-400a-task-timestamps-datetime]]), the view spec into the hub ([[261026-mb2a-view-spec-into-hub]]), and the repo's `ROADMAP.md` (animation themes, Projects view, close cascade).
ADR check: none. [[261025-r0ye-pkm-workbench-a-local-server]] already records the server; the status vocabulary change is flagged on its own task.
