# AKM spec review: defects, Prettier test, two proposals

Fresh-eyes review of [agent-ready-repo-spec](../spec/agent-ready-repo-spec.md) (the spec), [261027-ensf-akm-an-agent-knowledge-management](../adr/261027-ensf-akm-an-agent-knowledge-management.md) and [akm-guide](../spec/akm-guide.md) (the guide), with [agent-ready-repo-comparison](agent-ready-repo-comparison.md), [agent-ready-repo-discovery](agent-ready-repo-discovery.md) and four 2026-10-27 tasks read for context. Part of [261028-1z36-akm-spec-open-questions](../work/done/261028-1z36-akm-spec-open-questions.md). Nothing in the sources was changed; every fix below is a proposal. Section numbers (§) are the spec's unless stated. Ranking is my judgement of impact on someone implementing the standard.

## 1. The five most important findings

1. **Prettier is safe for frontmatter only if its YAML formatting is switched off.** With defaults, a flow list longer than 80 columns is broken over several lines and no longer fits H5; with `proseWrap: always`, a 160-character `summary` is folded onto continuation lines. With `embeddedLanguageFormatting: off`, frontmatter came back byte-identical in all 19 fixtures, under every prose-wrap setting. Details in §3.
2. **The generated ADR index (rule A5) is under-specified and collides with Prettier.** A5 demands byte equality with `akmctl index`, but the table layout (padding, escaping of `|`, empty groups, trailing newline) is nowhere defined. Prettier re-aligns pipe tables. The header comment still says `wb index`.
3. **H6 ("the tool is an accelerator") is false as written.** A bare agent cannot mint an id (R7 forbids it), run the checks, or regenerate the index. The fallback table covers only reading. The guide says "everything here works by hand today", which is not true for creating a record.
4. **Concurrency is the load-bearing gap.** The spec allows any number of `active` items and tells every agent to "resume" the active one; [261027-ensf-akm-an-agent-knowledge-management](../adr/261027-ensf-akm-an-agent-knowledge-management.md) and the guide promise "one active item". Two parallel agents will resume the same item. See proposal (a).
5. **Identifier clashes and stale rule ids.** Requirements R1 to R10 collide with roadmap rules R1 to R4; `W`/`E` are both severities and a rule prefix; `W2` does not exist; `D2b`, `D3b`, `D5b`, `D6b`, `D6c` are cited but defined nowhere; §4 says "no check" for accepted-body edits while rule A4 is that check.

## 2. Defect list

Format: location, what is wrong, proposed fix. Grouped by impact, highest first.

### High

1. **§0 H6, §2 fallbacks, guide §Status and §7.** The claim "everything the tool does is also possible by reading plain files" fails for writes. No fallback exists for: minting an id (R7), creating a record, running the checks, regenerating the index ("tell the maintainer"). _Fix:_ reword H6 to "every read is possible without the tool"; add a documented manual mint recipe (a one-line shell or Python snippet in the `AGENTS.md` template, using the same alphabet) and a "no tool" row for checks (a short list the agent verifies by eye); change the guide's status line.
2. **§0 H5 (the subset is not a grammar).** "Flat `key: value`, scalars and lists of scalars" leaves open: quoting and escapes, comments, empty values and `[]`, null, dates (typed or strings), duplicate keys, indentation of block lists, whether an inline list must fit on one line, continuation lines, CRLF and BOM. [261027-wkxv-go-yaml-library-evaluation](../work/done/261027-wkxv-go-yaml-library-evaluation.md) already lists requirements (quoted strings, dates, long values, block lists) that H5 does not state. The Prettier test (§3) shows the one-line rule matters. _Fix:_ add a normative grammar to §0 with accept and reject fixtures (the Appendix parser is a starting point).
3. **§4 "The generated index", rule A5.** Byte equality against generator output, but no format is specified. Prettier changes tables (§3); display width of CJK and emoji is 2 in Prettier, so a Go generator needs a matching width function. _Fix:_ specify the exact table (alignment, escaping, empty-group text, newline) and make it Prettier-stable, or compare after normalising whitespace; pick one ignore strategy (§3).
4. **§4 index comment `<!-- generated by wb index; do not edit -->`.** Old `wb` placeholder; A5 would compare against an `akmctl index` output that says something else. _Fix:_ `akmctl index`, and say whether the comment is part of the compared bytes.
5. **§2 rule "if an item is `active`, resume it"; ADR 261027-ensf "one active item"; guide §2, §6 "work one item at a time".** The spec has no limit on `active` items and no tie-break; the discovery note's drafted skill said "ask if several", which was lost. _Fix:_ decide: either add a rule (warn when more than one item is `active` in a repo, or per claimant) or reword the ADR and guide to "resume your item, or ask". Ties to proposal (a).
6. **§0 identifiers, §6 Rules, §9.** Clashes: R1 to R10 (requirements) against roadmap rules R1 to R4, and §9 cites "R1 to R4" for the roadmap; `W`/`E` are severities and the work-rule prefix (`W1 | E`); `W2` is missing (I1 sits where it would be), so §9 "W1 to W9" cites a gap; `H6` is listed before `H5` and the text says "H1 to H5"; `D2b`, `D3b`, `D5b`, `D6b`, `D6c` appear in the spec but not in the comparison (grep: no match); `P1` (X2) is undefined. _Fix:_ rename requirements to Q1 to Q10 (or rules to RM1 to RM4), rename work rules WK1 to WKn without a gap, move H6 after H5, define or drop the suffixed ids.
7. **§4 line "Acceptance … convention only; no check, D6c" against rule A4.** A4 is a check (warning). A4 also needs "the commit that accepted it", which is undefined for repos with no remote or with squash merges. _Fix:_ say "warning only" in §4; define how A4 finds the accepting commit (first commit where `status: accepted`) or drop A4 from v1.
8. **§7 Migration ships "as data in the template" against §6 "needs no network" and "the tool is installed separately".** The prebuilt binary has no way to read the template's `migrations/`. _Fix:_ embed migrations in the binary per version, or define `--template <path>`; state which.
9. **§6 Configuration `docs/.akm.toml`.** TOML needs a parser (the Go stdlib has none), against the stdlib-first goal and H5; "extra statuses" and "extra roadmap sections" contradict "MUST NOT use a status outside the enum" (§3), W3 and R2; it is a second config file beside `docs/.layout`; neither file is in the §1 tree. _Fix:_ put settings in `.layout` (H5 key-value), drop extra statuses or amend W3/R2 to allow them, add both files to §1.

### Medium

10. **Stale names for the old script.** §0 intro "rules of the check script"; R7 "minted by the script"; §2 "the docs check" (three times) and "the check script (D4)"; §8 "The script still runs", "The check script runs from the repo root"; §9 C6 "templates and script", C7 "One check script", C12 "standard library script". ## 3. Prettier test

**Question.** If the standard requires Prettier, does it leave frontmatter parseable under H5, and does it keep the generated ADR index?

**Setup.** Prettier 3.9.10 (npm `latest` on 2026-10-28; published 2026-10-10, 18 days old; the next tag is 4.0.0-alpha.13, not used). Node v26.11.1, npm 11.20.0, macOS. Run with `npx --yes prettier@3.9.10 --no-config --no-editorconfig <options> --write <dir>`; nothing global. Prettier's default `proseWrap` is already `preserve`, so "default" and "preserve" are the same run; I added `always`, `never` and `--print-width 1000` for contrast. Fixtures and parser: Appendix. 19 frontmatter fixtures plus a roadmap and an index table.

**Method.** `h5parse.py` parses each file before and after; a file passes if the parsed data is equal. Dates and integers are typed. `run.sh` and `compare.py` (Appendix) reproduce the table.

**Results (parse equal before and after).**

| Fixture                                                | default = preserve | always          | never           | width 1000 | embedded off (any wrap) |
| ------------------------------------------------------ | ------------------ | --------------- | --------------- | ---------- | ----------------------- |
| 160-char `summary`, plain                              | same               | **unparseable** | same            | same       | same                    |
| same, double-quoted                                    | same               | **unparseable** | same            | same       | same                    |
| same, single-quoted (rewritten to double quotes)       | same               | **unparseable** | same            | same       | same                    |
| ADR: 160-char summary, inline or block `scope`         | same               | **unparseable** | same            | same       | same                    |
| inline list, short                                     | same               | same            | same            | same       | same                    |
| inline list over 80 columns                            | **unparseable**    | **unparseable** | **unparseable** | same       | same                    |
| block list at indent 0, 2 or 4 (rewritten to indent 2) | same               | same            | same            | same       | same                    |
| quoted `:` and `#` in values                           | same               | same            | same            | same       | same                    |
| comments, unknown keys, `[]`, extra spaces             | same               | same            | same            | same       | same                    |
| dates, integers                                        | same               | same            | same            | same       | same                    |

Observations:

- **Safe rewrites:** single quotes become double quotes; block-list items are re-indented to two spaces; runs of spaces after `key:` collapse; a blank line is inserted after the frontmatter and between blocks in the body. None changes the parsed data.
- **Breaks H5:** (1) a flow list wider than 80 columns becomes a multi-line `[` … `]` (default, preserve, always, never); (2) `proseWrap: always` folds a long scalar onto indented continuation lines. A 160-character `summary` survives default and `preserve` because Prettier leaves plain and quoted scalars alone unless `always` is set.
- **Fix that worked:** `--embedded-language-formatting=off` (config: `"embeddedLanguageFormatting": "off"`). Prettier then skips the YAML block: frontmatter was byte-identical in all 19 fixtures, with `proseWrap: always` too. Cost: no normalisation of quotes or indentation in frontmatter (acceptable for H5). It also stops Prettier formatting fenced code in Markdown.
- **Weaker fixes:** an `overrides` entry with `printWidth: 200` for `docs/work/*.md` kept the long list on one line, but fails again past 200 columns. `# prettier-ignore` above a key worked for the long list; it needs a human to add it.
- **Roadmap:** `- [id] text` lines are unchanged apart from blank lines inserted between headings and lists; `- [ ]` and `- [x]` are unchanged.
- **Idempotence:** a second run changes nothing (`--check` exit 0).

**The ADR index table.**

- Prettier **re-aligns** a pipe table: `|---|---|` becomes padded `| --- |` with every column padded to the widest cell, in default, `preserve`, `always` and `width 1000`. With `proseWrap: never` it emits a compact, unpadded table. A generator's raw output fails `prettier --check` (exit 1); the aligned output passes.
- Width is display width: a CJK character and an emoji count as 2 columns, so a Go generator that pads to match Prettier needs the same width function (for example `go-runewidth`, not checked here). A `\|` in a cell is kept.
- **Options, with what I tested:**
  1. `.prettierignore` containing `docs/adr/README.md`: the file is skipped by `--check` (tested; `--write` not run; with `--ignore-path` the ignore file must be named explicitly). Simple, but the repo then has an unformatted file and every project needs the line.
  2. `<!-- prettier-ignore-start -->` / `<!-- prettier-ignore-end -->` around the tables, emitted by the generator: tested, the wrapped table is left alone and an unwrapped one is re-aligned. Works without a repo file; the markers are then part of the A5 bytes.
  3. A Prettier-stable generator (pads to display width, blank line after the header comment): tested indirectly (Prettier's own output passes `--check`). Most robust, but couples the generator to Prettier's width rules across versions.
- **Recommendation.** Require Prettier 3.x pinned in the template, with `{"embeddedLanguageFormatting": "off"}` so frontmatter is untouched; make the generator emit the aligned, Prettier-stable table and add the generated file to `.prettierignore` as a belt-and-braces measure; let A5 compare the generated bytes. Pin the Prettier version in the template and re-run this test on each bump (fixtures in the Appendix). H5 should then also say that an inline list stays on one line.

**What it answers in the open question.** The standard can require Prettier and still validate structure with its own parser, provided the shipped config switches embedded formatting off. Node is needed only to run Prettier. A `fmt` command is not needed.

## 4. Proposals (not decisions)

### (a) Who holds an `active` item

_Today:_ nothing. The vault's task-lifecycle skill treats an `active` note with a log line from another thread in the last day as taken, by convention only.

- **Option 1: advisory fields.** `claimed_by` (free string, for example `claude-code@mac` or a person) and `claimed_at` (UTC `YYYY-MM-DDTHH:MM`). Set by `akmctl claim <id> --as <name>` when moving to `active`; cleared by the same tool on any move out of `active` (`blocked`, `done`, `dropped`) or by `akmctl release`. A log line records each claim. Listings show the holder and the age.
- **Option 2: log convention only.** The first `## Log` line says "claimed (where)"; no field. Costs nothing; cannot be listed or checked.
- **Option 3: a shared lock** (a git ref or a lock file on a remote). The only real exclusion; needs a remote and network, and three of the maintainer's repos have none.
- **Failure behaviour (Option 1).** A claim is advisory, never a lock: it is visible only after it is committed and pushed. A claim older than the stale limit (default 24 h, configurable) is shown as stale, and any agent may take the item over by logging the takeover. A missing or unreadable claim means unclaimed. A holder that is not me means: do not work the item; tell the maintainer; take another `ready` item. Warn (W) on `active` without `claimed_by`, and on two `active` items with the same holder. Never block a commit.
- **Gaps it leaves.** Agents have no stable identity (use tool plus branch or session); two branches can claim the same item and meet only at merge (the field conflicts, which at least makes it visible).
- **Recommendation: Option 1,** with the stale rule, as an optional extension (`extension.claims`) so solo repos can skip it; add Option 2 as the no-tool fallback (a first log line).

### (b) A mechanical check for secrets or private text

- **Option 1: built-in patterns.** `akmctl check` scans records, `AGENTS.md` and `ROADMAP.md` for high-confidence shapes: private-key headers, AWS access key ids, GitHub and Slack token prefixes, JWT shape, `password: …` assignments; entropy-based hits are a warning only. Error on high confidence.
- **Option 2: a repo-declared deny list.** `docs/.akm-deny` holds literal strings or regexes the maintainer never wants in records (names, hostnames, account patterns, internal system names). Hits are errors. This is the only way to catch private text, and it is only as good as the list.
- **Option 3: delegate** to an external scanner (gitleaks, trufflehog) through a configured command run by `check` or a pre-commit hook. Best detection; adds a dependency and an optional network-free binary requirement.
- **What it can catch:** well-formed credentials; private-key blocks; declared strings; accidental pastes of tokens into a `## Log`.
- **What it cannot catch:** secrets with no fixed shape; private writing or employer material described in ordinary prose; copyrighted text; paraphrase; anything already committed (history); files outside the scanned set. A pass means "no known pattern", not "safe". Say so in the finding text and the guide.
- **Safety of the tool itself:** print the file, line and rule id, never the matched text, so a secret is not copied into logs or agent context. An inline allow marker needs a reason and is itself listed by `check`.
- **Recommendation:** Options 1 and 2 built in (small, no dependency), Option 3 as an adapter. Run in `check` and in a pre-commit hook; keep the C11 gap statement in §9 but narrow it to "no check beyond known patterns and the deny list".

## Appendix: fixtures, parser and scripts

### `h5parse.py` (the H5 subset parser; my reading of H5)

```python
#!/usr/bin/env python3
"""Parser for the AKM H5 frontmatter subset. Usage: h5parse.py FILE... (prints JSON, or ERROR)."""
import json, re, sys

KEY = re.compile(r'^([A-Za-z_][A-Za-z0-9_.-]*):(?:[ \t]+(.*))?$')
DATE = re.compile(r'^\d{4}-\d{2}-\d{2}$')
INT = re.compile(r'^-?\d+$')

class H5Error(Exception):
    pass

def split_frontmatter(text):
    lines = text.split('\n')
    if lines[0] != '---':
        raise H5Error('no opening ---')
    for i in range(1, len(lines)):
        if lines[i] == '---':
            return lines[1:i], '\n'.join(lines[i + 1:])
    raise H5Error('no closing ---')

def strip_comment(s):
    """Remove a trailing ' #...' outside quotes."""
    q = None
    for i, ch in enumerate(s):
        if q:
            if ch == q:
                q = None
        elif ch in '"\'':
            q = ch
        elif ch == '#' and (i == 0 or s[i - 1] in ' \t'):
            return s[:i].rstrip()
    return s

def scalar(s):
    s = s.strip()
    if s == '':
        raise H5Error('empty scalar')
    if s[0] == '"':
        if len(s) < 2 or s[-1] != '"':
            raise H5Error('unterminated double quote: ' + s)
        body = s[1:-1]
        if re.search(r'(?<!\\)"', body):
            raise H5Error('stray quote: ' + s)
        return ('str', body.replace('\\"', '"').replace('\\\\', '\\'))
    if s[0] == "'":
        if len(s) < 2 or s[-1] != "'":
            raise H5Error('unterminated single quote: ' + s)
        body = s[1:-1]
        if re.search(r"(?<!')'(?!')", body):
            raise H5Error('stray quote: ' + s)
        return ('str', body.replace("''", "'"))
    if s[0] in '[{|>&*!%@`' or s.startswith('- '):
        raise H5Error('unsupported scalar start: ' + s)
    if ': ' in s or s.endswith(':'):
        raise H5Error('plain scalar contains ": ": ' + s)
    if INT.match(s):
        return ('int', int(s))
    if DATE.match(s):
        return ('date', s)
    return ('str', s)

def inline_list(s):
    inner = s[1:-1].strip()
    if inner == '':
        return []
    items, cur, q = [], '', None
    for ch in inner:
        if q:
            cur += ch
            if ch == q:
                q = None
        elif ch in '"\'':
            q = ch
            cur += ch
        elif ch == ',':
            items.append(cur)
            cur = ''
        else:
            cur += ch
    if q:
        raise H5Error('unterminated quote in list')
    items.append(cur)
    if items and items[-1].strip() == '':
        items.pop()  # trailing comma
    out = []
    for it in items:
        if it.strip().startswith(('[', '{')):
            raise H5Error('nested flow collection')
        out.append(scalar(it)[1])
    return out

def parse(text):
    fm, body = split_frontmatter(text)
    data, i = {}, 0
    while i < len(fm):
        line = fm[i]
        if line.strip() == '' or line.lstrip().startswith('#'):
            i += 1
            continue
        if line[0] in ' \t':
            raise H5Error('indented line outside a list (continuation or nesting): ' + repr(line))
        m = KEY.match(line)
        if not m:
            raise H5Error('not key: value: ' + repr(line))
        key, val = m.group(1), m.group(2)
        if key in data:
            raise H5Error('duplicate key ' + key)
        val = strip_comment(val) if val else ''
        if val == '':
            items = []
            j = i + 1
            while j < len(fm) and (fm[j].strip() == '' or fm[j].lstrip().startswith('#') or re.match(r'^\s*- ', fm[j])):
                if re.match(r'^\s*- ', fm[j]):
                    items.append(scalar(strip_comment(re.sub(r'^\s*- ', '', fm[j])))[1])
                j += 1
            data[key] = items if items else None
            i = j
            continue
        if val.startswith('['):
            if not val.endswith(']'):
                raise H5Error('inline list not closed on one line: ' + val)
            data[key] = inline_list(val)
        else:
            t, v = scalar(val)
            data[key] = v if t != 'date' else {'date': v}
        i += 1
    return data, body

if __name__ == '__main__':
    for p in sys.argv[1:]:
        try:
            d, _ = parse(open(p, encoding='utf-8').read())
            print(p, json.dumps(d, sort_keys=True))
        except H5Error as e:
            print(p, 'ERROR', e)
```

### `compare.py` (parse before and after, print the table)

```python
#!/usr/bin/env python3
"""Compare H5-parsed data before (src/) and after (out/<cfg>/) Prettier. Prints a table."""
import os, sys
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
import h5parse
cfgs = sys.argv[1:] or ['default','preserve','always','never','wide']
files = sorted(f for f in os.listdir('src') if f.startswith(('w','a')))
print('file'.ljust(34) + ''.join(c.ljust(10) for c in cfgs))
bad = {}
for f in files:
    before = h5parse.parse(open('src/'+f).read())[0]
    row = f.ljust(34)
    for c in cfgs:
        try:
            after = h5parse.parse(open(f'out/{c}/{f}').read())[0]
            res = 'same' if after == before else 'CHANGED'
            if res != 'same': bad[(f,c)] = ('changed', before, after)
        except h5parse.H5Error as e:
            res = 'UNPARSE'; bad[(f,c)] = ('unparse', str(e))
        row += res.ljust(10)
    print(row)
if '-v' in os.environ.get('V',''):
    pass
import json
json.dump({f'{k[0]}|{k[1]}': v for k,v in bad.items()}, open('bad.json','w'), indent=1, default=str)
```
