### Findings (candidates)

Each has an area, a severity (gap, risk or nuisance), the evidence and a recommended fix.

- **C1. The bindings do not run the contract.** Area: conformance fixtures. Severity: gap. Evidence: `grep -rn "testdata/api/cases" internal` finds one reader, `internal/api/conformance_test.go`, which calls `api.Run`. The CLI and the HTTP server have their own hand-written tests, and `docs/architecture.md` states that "the CLI and the HTTP binding return the same JSON envelope for the same request"; I found no test that runs one request through both and compares. Fix: run every case file through the HTTP handler and, for the reads, through the CLI with `--format json`, and compare with `expected`.
- **C2. Operations with no fixture.** Area: conformance fixtures. Severity: gap. Evidence: `ls docs/spec/akm-api/.fixtures/cases` has no `commits-*`, `history-*` or `skills-*` file, and the only `new` case (`new-1`) is a refusal. The reason is real: ids are random (API spec section 10) and a fixture directory cannot hold a git history. Fix: an ADR on how to fixture these (a fixed clock and id source for `new`; a fixture that builds a git history from a script for `commits` and `history`); see the draft ADR list in the closing item.
- **C3. Tests that need an outside tool skip without a word.** Area: tooling. Severity: risk. Evidence: `t.Skip` in `internal/server/ui_assets_test.go` (no `node`), four test files in `internal/api` (no `git`; two more use it), `internal/check/safety_test.go` (`AKM_CORPUS` not set, a corpus that no job sets). A runner without Node or git would pass with the workbench and every git feature untested. Fix: in CI, fail when the tool is missing (an environment variable such as `AKM_REQUIRE_TOOLS=1` turns each skip into a failure), and decide whether the corpus test belongs in CI.
- **C4. The workbench has no test for its page code.** Area: workbench. Severity: gap. Evidence: `ls internal/server/web/js` lists 25 modules; `TestPureModulesUnderNode` loads 14 of them (`util logic store live moves project review capture controls effects fields picker toasts replay`). The 11 modules that touch the DOM (`adrs anim board boot check detail flow rows tables ui wizard`) have no automated test; the pull requests that changed them say what was checked by eye in the browser pane. Fix: a DOM test with a small fake `document` for the render functions, or a recorded browser run; at least a smoke test that `boot.js` renders the board against a fixture repository.
- **C5. The scripts that users run have no test.** Area: tooling. Severity: risk. Evidence: `scripts/install.sh` (73 lines, piped from `curl` to `sh` by the README) and `scripts/release.sh` (56 lines) appear in no test; `release.yml` runs only on a tag, so a break in the release script shows up when a release is cut. `cmd/akmctl` also has no test file. Fix: a CI job that runs `scripts/release.sh` for a dummy version and runs `install.sh` against the produced archive in a temporary directory.
- **C6. What the skills tell an agent is not tested.** Area: skills. Severity: gap. Evidence: the tests above check copies, names and operation references. The text is checked only by hand: the cold-agent trial of 261101-baze and its retest in 261101-t8h8, which found two tool snags (261108-h7ds, 261108-kdz1) that no test had pinned. Fix: keep a small scripted cold-agent check as a recorded procedure, and add a test for each snag a retest finds.
- **C7. CI proves less than it looks like on two platforms.** Area: platform. Severity: risk. Evidence: `ci.yml` runs `go test -race` only when `runner.os == 'Linux'`; `AGENTS.md` says to add `-race` on Linux or macOS. The Windows job has `continue-on-error`, and it fails on every pull request (known; Windows debugging is on hold), so a Windows-only regression is invisible among the existing failures. Fix: add `-race` on macOS; when Windows work resumes, make the known failures a named skip list so a new failure shows.
- **C8. Fuzz targets only run their seeds.** Area: tooling. Severity: nuisance. Evidence: `grep -rln "func Fuzz" internal` finds `internal/frontmatter/fuzz_test.go` and the body tests; CI runs plain `go test`. Fix: a scheduled or manual job with `-fuzz` for a minute per target.
